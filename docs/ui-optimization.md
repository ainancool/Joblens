# SG Job Lens 0.8.0：UI 分析与优化说明

## 分析结论

这是一个原生 Chrome Manifest V3 侧栏插件，而不是网站：`content.js` 读取 LinkedIn 职位，`background.js` 查询 MyCareersFuture（MCF），`lib.js` 在本地完成匹配和薪资统计。简历通过 pdf.js / fflate 本地提取，插件不调用 LLM，只生成提示词并复制或打开 Claude / ChatGPT。

原 ZIP 共13个文件。核心功能已经完整，主要可用性问题集中在 `sidepanel.js`：界面、CSS和交互混在同一个脚本，顶部字号偏小，薪资页先展示匹配依据再展示结论；AI按钮叫“发送”，但实际上只是打开网站；简历草稿与保存状态不够明确，保存失败可能被误报为成功；查询失败和无职位状态只有短提示，缺少可操作的恢复路径。窄侧栏下的多项筛选和长说明也容易挤在同一行。

## 本次改动

| 原问题 | 0.8.0 的优化 | 对用户的作用 |
|---|---|---|
| 首屏堆叠依据和多个数值 | 先展示同公司职位的公开基本月薪，再分别展示公司与市场参考；依据可展开 | 先看结论，再按需核对来源 |
| “完全匹配”容易被误认为已确认薪酬 | 改为“公司与职位名匹配”；可能匹配明确要求核对原帖 | 不把规则匹配冒充 LinkedIn 雇主的确认报价 |
| 分位数和参考性难理解 | 标注“中间50%岗位”、中位数、样本数；小样本和经验放宽单独提示 | 区分统计区间、原职位薪资和数据局限 |
| 导航和小图标不易识别 | 四页保留，采用一致图标/文字、明显选中状态、键盘左右/Home/End切换 | 侧栏可快速浏览，也支持键盘操作 |
| 查询失败、无职位时缺少下一步 | 入门步骤、骨架加载、错误详情、重试与AI替代入口；30秒界面查询超时 | 不再只看到空白或原始报错 |
| 筛选挤在一行 | 独立换行筛选：全部、薪资相仿、薪资更高、未公开；无结果可返回全部 | 窄侧栏内更容易发现有用岗位 |
| AI“一键发送”含义模糊 | “简历 → 任务 → 完整预览 → 复制/打开”三步；明确不自动提交消息 | 用户能先确认内容和去向 |
| 复制或弹窗失败仍可能误报 | 显示真实状态，保留手动复制/打开路径；长文本不塞进过长URL | 避免内容截断与操作误解 |
| 简历状态和存储反馈不明确 | 显示已保存/未保存更改、字数上限、导入忙态；保存失败保留草稿；删除需确认 | 减少误覆盖和经历丢失 |
| 页面重绘丢失阅读位置 | 保留当前职位内的滚动、可识别焦点、文本选择和展开状态 | 查询或切页时更稳定 |
| JD延迟加载时提示词可能过期 | JD增长时废弃旧预览，并提示薪资依据可能需刷新 | 防止把旧内容当成完整描述 |
| 提示词引用了扩展自身地址 | 修正为真实 LinkedIn 职位链接 | AI上下文不再包含无用的扩展地址 |

采用低干扰的青绿/深蓝设计、浅色卡片和统一间距，支持系统深色模式。字体、图标和样式都在插件内部，不依赖外部字体、图标服务或额外网页。

## 简历与 AI 的真实行为

简历仍只保存在 `chrome.storage.local`。支持 PDF/DOCX/TXT/MD，文件不超过8MB，PDF最多读取20页；扫描PDF可能没有可提取的文字，需先做OCR或直接粘贴。手动粘贴超过20,000字符时禁止保存，避免静默截断；文件提取仍继承原解析器20,000字符上限，TXT/MD超过上限会额外提示。

生成预览不会打开AI网站。点击“复制”会将文本写入系统剪贴板；点击“打开AI对话”才会把预览内容带到所选网站。短提示词尝试用URL预填；长提示词完整复制后打开空对话，需要用户粘贴。网站是否保留预填内容取决于对方实现，仍需核对并自行发送；AI网站可能要求登录。

## 保持不变的部分

`lib.js`、`content.js`、`background.js`、`resume-extract.js`和vendor文件按字节保持不变。MCF查询、月薪换算、公司名匹配、样本统计、职位相似度、经验过滤规则和24小时缓存契约没有修改；新增筛选只作用于现有结果，不宣称查询整个市场。

Chrome权限仍为 `storage` / `sidePanel`，MCF的host permission与LinkedIn content script范围不变。没有新增账户系统、API Key、后端、遥测、自动简历上传或自动投递。

代码改动为 `sidepanel.js` 的UI/状态处理，新增 `sidepanel.css`，HTML引用样式，manifest版本号更新为0.8.0，以及说明/回归文件。

## 安装与更新

1. 解压优化版ZIP，在 `chrome://extensions` 开启开发者模式。
2. 新安装：选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的 `sg-job-lens` 文件夹。不要直接选择ZIP或其上级目录。
3. 已安装旧版：先备份原插件文件夹；将新版文件放到原加载路径，再点击扩展卡片的“重新加载”。不要先卸载旧扩展，以免Chrome清掉旧扩展存储。更换加载路径也可能改变扩展ID，新ID不会自动迁移旧简历。
4. 刷新已经打开的LinkedIn职位页，再点击工具栏图标或Alt/Option + Shift + J打开。

顶部刷新只清除职位查询缓存，不删除已保存简历。旧版已保存的简历与AI目标继续使用原storage key。

## 验证与限制

验收包含原算法固定样本断言、真实Chromium页面交互、320/400/600px与浅/深色共24种页面组合，以及真实Chrome加载已解压MV3扩展的完整消息链验证。前后预览均使用同一组虚构固定样本，**不是实时薪资数据**。

本轮没有登录用户LinkedIn、没有真实调用MCF，也没有向Claude/ChatGPT发送用户材料。真实扩展验收拦截LinkedIn页面并在service worker中返回固定MCF响应，主要证明打包、内容脚本、后台算法、侧栏和Chrome存储可协同工作；不证明未来MCF接口或LinkedIn DOM永远兼容。

原解析器仍不支持OCR，AI仍只生成提示词而不自动执行模型，技能词表偏技术岗位、公司名规则匹配和缓存仅区分JD是否存在等原限制仍保留。界面会解释这些边界，而不是伪造完整数据或确定的求职成功概率。

设计参考：[Chrome官方Side Panel UX指导](https://developer.chrome.com/blog/extension-side-panel-launch)。
